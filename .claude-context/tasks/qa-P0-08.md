## 1. SIMPLIFY KONTROLA

### ⚠️ Hardcoded developer-specific URL — 4 duplicitní výskyty

Řetězec `"postgresql://zen@localhost:5432/carmakler"` je hardcoded na 4 místech:

| Soubor | Řádek |
|--------|-------|
| `lib/prisma.ts` | 10 |
| `prisma/seed.ts` | 6 |
| `prisma/seed-partners.ts` | 7 |
| `prisma.config.ts` | 7 |

**Problémy:**
1. **DRY porušení** — stejný řetězec na 4 místech, změna vyžaduje úpravu všech
2. **Developer-specific** — `zen` je lokální username, na jiném stroji (CI/CD, jiný vývojář) selže s `role "zen" does not exist`
3. **Plán specifikoval** (Krok 3): jednoduché `new PrismaClient()` bez fallback URL — pokud DATABASE_URL chybí, má Prisma selhat hlasitě, ne tiše padnout na špatnou DB

**Doporučení:**
```ts
// Místo:
const connectionString = process.env.DATABASE_URL || "postgresql://zen@localhost:5432/carmakler";

// Použít:
const connectionString = process.env.DATABASE_URL;
if (!connectionString) {
  throw new Error("DATABASE_URL není nastavena");
}
```

Nebo alespoň sjednotit na generický fallback bez uživatelského jména: `"postgresql://localhost:5432/carmakler"`.

### Dokumentované odchylky od plánu (všechny legitimní)

Implementátor odůvodnil v `impl-P0-08.md`: **Prisma 7.5.0 nepodporuje `url` v `schema.prisma`** — vyžaduje adapter pattern.

| Odchylka | Co plán říkal | Co je implementováno | Zdůvodnění |
|----------|---------------|----------------------|------------|
| `schema.prisma` — no `url` | `url = env("DATABASE_URL")` | Bez url (Prisma 7 pattern) | Prisma 7 nepodporuje url v schema při adapter použití |
| `prisma.config.ts` — datasource ponechán | Odstranit datasource blok | Datasource s URL pro migrate | Migrate potřebuje URL; adapter pattern ho nedodá |
| `lib/prisma.ts` — `PrismaPg` adapter | `new PrismaClient()` | `PrismaPg` + `pg.Pool` | Prisma 7 vyžaduje adapter pro pg připojení |

**Všechny 3 odchylky jsou technicky správné pro Prisma 7.5.0.** ✅
