## P1-05: Resend email centralizace

### Simplify kontrola
Výborná centralizace. Z 8 souborů s duplicitním `new Resend(process.env.RESEND_API_KEY)` na jeden sdílený modul.

#### ⚠️ Design poznámka: `RESEND_FROM_CONTRACTS` sdílí env var s `RESEND_FROM`

```ts
export const RESEND_FROM = process.env.RESEND_FROM_EMAIL || "info@carmakler.cz";
export const RESEND_FROM_CONTRACTS = process.env.RESEND_FROM_EMAIL || "smlouvy@carmakler.cz";
```

Pokud je `RESEND_FROM_EMAIL=info@carmakler.cz` nastaveno (což `.env.example` doporučuje), pak `RESEND_FROM_CONTRACTS` vrátí `info@carmakler.cz` místo `smlouvy@carmakler.cz`. Smlouvy budou odesílány ze stejné adresy jako ostatní emaily.

Toto je shodné s plánem (implementace odpovídá specifikaci), ale je to potenciálně matoucí chování. Doporučuji přidat `RESEND_FROM_CONTRACTS_EMAIL` do `.env.example` pro budoucí oddělení.

#### ⚠️ Lint job chybí `prisma generate`

Job `lint` (řádky 21-38) NEspouští `npx prisma generate` před `npm run lint`. ESLint s pluginem `next/typescript` používá TypeScript parser, který potřebuje vygenerované typy z `@prisma/client`. V projektu je 6 souborů importujících `from "@prisma/client"` (`lib/prisma.ts`, `prisma/seed.ts`, `prisma/seed-partners.ts`, a 3 API routes). Lint job MŮŽE selhat v CI pokud parser nedokáže resolvovat Prisma typy.

**Doporučení:** Přidat `npx prisma generate` před lint krok v CI.

#### ✅ Prisma generate před typecheck, test, build

#### ✅ Dummy env vars v build jobu
```yaml
DATABASE_URL: "postgresql://dummy:dummy@localhost:5432/dummy"
NEXTAUTH_SECRET: "ci-build-secret-not-real"
NEXTAUTH_URL: "http://localhost:3000"
NEXT_PUBLIC_APP_URL: "http://localhost:3000"
```

#### ✅ `package.json` typecheck script
```json
"typecheck": "tsc --noEmit"
```

#### ⚠️ Potenciální risk: `DATABASE_URL` v typecheck/test jobech

`prisma generate` v `typecheck` a `test` jobech nemá `DATABASE_URL`. Místo toho použije hardcoded fallback z `prisma.config.ts`: `"postgresql://zen@localhost:5432/carmakler"`.

- **Dopad na CI:** `prisma generate` nepotřebuje reálné DB připojení — jen čte schema a generuje TypeScript typy. Fallback URL stačí.
- **Závažnost:** Nízká — CI projde. Je to stejný portability concern jako v P0-08 (hardcoded username `zen`).
- **Shodné s plánem** — plán také nemá DATABASE_URL v typecheck/test jobech.
