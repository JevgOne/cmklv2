## Nalezene problemy

### MINOR: Nekonzistentni navratovy typ v catch blocich (lib/stats.ts)

**Soubor:** `lib/stats.ts`, radky 64 a 130

**Popis:** Obe funkce v catch bloku vraci cely `DEFAULTS` objekt (6 poli), zatimco v happy path vraci jen 3 relevantni pole. Napr. `getBrokerStats()` v catch vraci i `completedFlips`, `avgROI`, `avgFlipDays` navic.

**Dopad:** Zadny runtime dopad (TypeScript strukturalni typovani extra pole toleruje, UI je nepouzije). Ale je to neprehledne a ztezuje budouci refactoring.

**Doporuceni:** Rozdelit DEFAULTS na dva separatni objekty:
```ts
const BROKER_DEFAULTS = { soldVehicles: 0, avgSaleDays: 0, avgRating: 0 };
const MARKETPLACE_DEFAULTS = { completedFlips: 0, avgROI: 0, avgFlipDays: 0 };
```

### MINOR: Hardcoded "+21%" v marketplace hero ilustraci

**Soubor:** `app/(web)/marketplace/page.tsx`, radek 194

**Popis:** V dekorativnim hero bloku zustava `+21%` jako staticky text ("Prumerny rocni vynos"). Neni to dynamicka stat z DB, ale marketingovy claim.

**Dopad:** Nizky — je to v ilustracnim boxu (skryty na mobile), vizualne oddeleny od dynamickych stat. Ale muze casem divergovat od skutecneho `stats.avgROI`.

**Doporuceni:** Zvazit nahrazeni `stats.avgROI > 0 ? \`+${stats.avgROI}%\` : "+21%"` nebo ponechat jako staticke s komentarem `{/* Marketingovy claim, ne DB stat */}`.

### INFO: Staticke "20 dni" v benefits a FAQ (chci-prodat)

**Soubor:** `app/(web)/chci-prodat/page.tsx`, radky 43 a 76

**Popis:** V sekci "Proc prodat" (benefit title) a FAQ odpovedi zustava staticke "20 dni". Hero stats sekce je spravne dynamicka.

**Dopad:** Nizky — benefits a FAQ jsou marketingove texty, ne realtimove statistiky. Ale muze divergovat od dynamicke hero hodnoty.

**Doporuceni:** Ponechat — jsou to marketingove texty s kontextem ("prumerna", "zalezi na..."). Pripadne pridat komentar.
