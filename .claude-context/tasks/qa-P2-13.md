## 2. Debug kontrola

### Bezpecnost

- Token entropy: 256 bit (32 bytes = 64 hex chars) -- brute force infeasible
- Stare tokeny invalidovany pri novem generovani
- Used flag zabranuje reuse
- 24h expirace
- Resend rate limit (3x/hod per IP, neodhaluje existenci emailu)
- Admin endpoint: session + role check

### TOFU (Token On First Use) edge case

`/overeni-emailu/[token]/page.tsx` je Server Component, ktery vola `verifyEmailToken()` primo pri nacteni stranky. Pokud email klient zobrazi preview odkazu, token se spotrebuje PRED klikem uzivatele. Pote uzivatel uvidi "Odkaz jiz byl pouzit".

Toto je akceptovany trade-off (stejny pristup jako v planu). Mitigace: uzivatel muze pozadat o novy email pres resend.

### Duplicitni verifikacni cesty

Existuji DVE cesty k verifikaci tokenu:
1. `app/(web)/overeni-emailu/[token]/page.tsx` -- Server Component (primarni -- email link vede sem)
2. `app/api/auth/verify-email/[token]/route.ts` -- API route (alternativni -- pro programove pouziti)

Obe volaji `verifyEmailToken()`. Neni konflikt -- druhe volani vrati "Odkaz jiz byl pouzit". Pripustne.

### Rate limit resend

In-memory Map-based (`lib/rate-limit.ts`). Neresetuje se pri restartu serveru, ale funkcne spravne. Pro single-instance deployment dostatecne.
