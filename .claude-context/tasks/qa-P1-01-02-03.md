## Doporuceni (nizka priorita):

### 1. [P1-03] Dead code: loading.tsx a error.tsx v inzerce/katalog
- **Zavaznost:** VELMI NIZKA (kodova hygiena)
- **Popis:** Po nahrazeni stranky redirectem jsou `loading.tsx` a `error.tsx` v `app/(web)/inzerce/katalog/` dead code — nikdy se nezobrazí. Plan zminoval volitelne smazani.
- **Fix:** Smazat oba soubory: `app/(web)/inzerce/katalog/loading.tsx` a `app/(web)/inzerce/katalog/error.tsx`.

### 2. [P1-03] redirect() vs permanentRedirect() pro SEO
- **Zavaznost:** NIZKA
- **Popis:** `redirect()` vraci HTTP 307 (temporary), coz Google interpretuje jako "muze se zmenit". Pro trvalou zmenu URL by `permanentRedirect()` z `next/navigation` nebo `next.config.ts` redirect s `permanent: true` (HTTP 308) byl lepsi pro konsolidaci SEO signalu.
- **Fix:** Zmenit `redirect("/nabidka")` na `permanentRedirect("/nabidka")` a pridat import.

### 3. [P1-01] userName fallback — nacist jmeno z User modelu
- **Zavaznost:** VELMI NIZKA (UX zlepseni)
- **Popis:** `recipientEmail.split("@")[0]` jako userName neni idealni (napr. "jan.novak" misto "Janu"). Prisma query uz nacita `user: { select: { email: true } }` — stacilo by pridat `firstName: true`.
- **Fix:** V matchWatchdogs() query pridat `user: { select: { email: true, firstName: true } }` a v sendWatchdogEmail pouzit `watchdog.user?.firstName || recipientEmail.split("@")[0]`.

### 4. [P1-01] Typ parametru slug zbytecne nullable
- **Zavaznost:** VELMI NIZKA (typova presnost)
- **Popis:** `slug: string | null` v sendWatchdogEmail, ale Prisma schema ma `slug String @unique` (NOT NULL). Typ je zbytecne volny.
- **Fix:** Zmenit na `slug: string` a odstranit `|| l.id` fallback v URL sestaveni.
